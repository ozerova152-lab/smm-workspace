# SMM Workspace

Локальное пространство для контент-плана и аналитики по выбранным площадкам: проекты, карточки, календарь, ручные замеры и импорт CSV. Работает без регистрации и подключения социальных сетей. Данные рабочей копии сохраняются в браузере на этом компьютере.

## Установка и первый запуск

1. Установите [Node.js 24](https://nodejs.org/) с npm и Git. Откройте терминал в папке, где хотите разместить проект.
2. Выполните `git clone https://github.com/ozerova152-lab/smm-workspace.git` и перейдите в папку командой `cd smm-workspace`. Если вы скачали архив, распакуйте его и откройте терминал в папке с `package.json`.
3. Выполните команды:

   ```sh
   npm ci
   npm start
   ```

4. Откройте [http://127.0.0.1:3000/](http://127.0.0.1:3000/), нажмите «Создать проект» и сохраните тестовое название. Остановите приложение в терминале клавишами Ctrl+C, снова выполните `npm start` и откройте тот же адрес в том же браузере: проект останется на месте.

В Windows, если PowerShell блокирует `npm`, используйте `npm.cmd ci` и `npm.cmd start`. Если порт 3000 занят, закройте прежний запуск приложения или освободите порт. Смена адреса или профиля браузера создаёт отдельное хранилище.

## Данные и резервная копия

Рабочие записи хранятся локально в IndexedDB браузера. Очистка данных сайта или удаление профиля браузера может их удалить. В разделе «Резервная копия» на странице проектов скачайте JSON и храните его вне папки проекта; там же можно восстановить данные. Файл содержит ваши данные: не публикуйте его и не передавайте без необходимости.

На главной странице кнопка «Открыть пример данных» показывает вымышленные проекты. Изменения в примере сбрасываются при перезагрузке. Чтобы вернуться к своим данным, нажмите «К рабочему пространству». Ручной ввод и импорт CSV доступны без MCP; доступы к социальным сетям настраиваются отдельно в коннекторе, а не в исходниках.

## Демонстрация и проверки

[Открыть публичное демо](https://ozerova152-lab.github.io/smm-workspace-demo/). Для локальной подготовки статической демосборки выполните `npm run build:demo`: файлы появятся в `dist-demo`. В демо используются вымышленные данные, изменения не сохраняются после перезагрузки.

`npm run check` запускает проверку кода, модульные тесты и сборку. Для браузерных тестов установите Chromium командой `npx playwright install chromium`, затем выполните `npm run test:e2e`. Подробнее: [настройка и проверки](docs/dev/setup.md), [сценарии](docs/spec/04-user-flows.md).
