# Локальное окружение SMM Workspace

## Резервная копия

В локальном режиме откройте «Резервная копия» на странице проектов. «Скачать копию» сохраняет проекты, площадки, карточки, замеры, референсы и стратегию в JSON. Для восстановления выберите этот файл. Перед заменой текущего набора проверьте количество записей и подтвердите замену. В рабочей копии эти данные сохраняются в IndexedDB и доступны после запуска в том же профиле браузера. Копия позволяет перенести весь набор в другой профиль.

## Сводка для агента

В «Аналитике» выберите площадку, период, нужные строки и референсы. Нажмите «Скачать сводку» и передайте JSON агенту в отдельном запросе. Пример запроса: «Сравни публикации только по одинаковой метрике, источнику и окну замера. Приведи цифры и предложи две идеи для следующего плана. Если данных мало, скажи об этом». Выбранную идею добавьте через «Добавить идею» в контент-плане. [Пример отчёта с вымышленными данными](analytics-report-example.md).

Для обратного импорта скачайте шаблон CSV. В `publication_id` укажите внешний ID публикации или точную ссылку из карточки. Ранее выгруженные CSV с внутренними ID карточек тоже можно импортировать. Пустое значение относится к площадке целиком. Для снимка на одну дату заполните `window_start` и оставьте `window_end` пустым. Единицу и окно можно задать в настройках метрик площадки, например «Просмотры | шт. | Первые 7 дней». Эти сведения показаны при ручном вводе и в строках импорта с соответствующим названием метрики. В демо импорт открывает готовый пример. Рабочие файлы можно выбирать в локальном режиме.

## Запуск

Установите Node.js 24 с npm. Для работы с историей проекта понадобится Git.
В корне проекта выполните `npm ci`, затем `npm start`. Откройте [рабочую копию](http://127.0.0.1:3000/). Остановите процесс сочетанием Ctrl+C. Если порт 3000 занят, завершите предыдущий запуск SMM Workspace или освободите порт. Для сохранённых данных используйте один и тот же адрес и профиль браузера.

На Windows в PowerShell можно использовать `npm.cmd` вместо `npm`, если настройки PowerShell блокируют запуск скрипта npm.

## Вымышленные данные

На странице выберите «Открыть пример данных», чтобы увидеть два вымышленных проекта. Изменения в демо хранятся в памяти текущей страницы. Для просмотра состояний добавьте к адресу `?state=loading`, `?state=error` или `?state=platform-error`. Заготовки карточек и метрик находятся в `src/fixtures.ts` и `fixtures/sample-metrics.csv`. Для запуска и проверок секреты не требуются. Доступы к социальным сетям настраиваются в коннекторе агента.

## Проверки

- `npm run check` проверяет код, типы и сборку.
- `npx playwright install chromium` устанавливает браузер для проверок. Чтобы хранить его в папке проекта, установите `PLAYWRIGHT_BROWSERS_PATH=0` перед установкой и запуском проверок.
- `npm run test:e2e` проходит первый запуск и проверяет настройки анимации в отдельном браузерном контексте. Скриншоты состояний сохраняются в `test-results/`.
- `workspace-start` и `workspace-check` содержат эти шаги для агента.
