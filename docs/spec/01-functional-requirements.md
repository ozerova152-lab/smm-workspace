# Функциональные требования SMM Workspace

> Слой 1 из 3. Черновик на согласование.

SMM Workspace — русскоязычное рабочее пространство, где можно планировать контент по любым выбранным площадкам, видеть ход работы и использовать результаты публикаций для следующего плана.

**Аудитория.** Первая версия для русскоязычных SMM-специалистов в любой стране, в том числе работающих в команде или компании. У локальной копии один владелец, каталог площадок международный. Для команд, которым нужен совместный доступ, понадобится отдельная версия. Продукт рассчитан на SMM и контент-менеджмент. Сквозной маркетинг, продажи и рекламные кабинеты находятся за его пределами.

## Возможности первой версии

| Возможность | Критерий готовности |
|---|---|
| Дашборд проектов | Дано несколько проектов с карточками. Когда владелец открывает главную, он видит площадки, ближайшие публикации, незавершённые задачи и следующие шаги. Может сравнить проекты по числу запланированных, опубликованных и просроченных карточек за выбранный период и открыть нужную карточку. |
| Настраиваемые площадки | Дан проект бренда, клиента или направления. Когда владелец добавляет площадку из каталога или создаёт свою, он может настроить её форматы, метрики и чек-лист. На странице площадки видны её идеи, план, шаблоны и результаты. |
| Контент-план | Даны карточки нескольких площадок. Когда владелец добавляет, переносит или убирает публикацию, изменение видно в календаре, доске и таблице. При открытии проекта по умолчанию видна таблица всех его площадок. Вход со страницы площадки открывает её календарь. Есть фильтры по площадке и типу работы внутри проекта. |
| Карточки и статусы | Дана идея. Когда владелец готовит её адаптации, у каждой есть своя площадка, формат, аудитория, статус, срок подготовки, дата выхода, ссылка и следующий шаг. Он может связать с публикацией сценарий, раскадровку и обложку. Производственная доска показывает «Идея → В работе → На проверке → Готово → Опубликовано». Для аналитики видны состояния «Ожидает данных» и «Обновлено». |
| Шаблоны | Дана библиотека шаблонов постов, видео, SEO-описаний и сопроводительных писем. Когда владелец применяет шаблон, он получает редактируемую копию, а оригинал остаётся в библиотеке. |
| Заметки к стратегии | Дан проект и выводы по публикациям. Когда владелец сохраняет цель, аудиторию или гипотезу для следующего периода, он может открыть заметку из проекта при корректировке контент-плана. |
| Базовая аналитика | Дана опубликованная карточка. Когда владелец вносит или импортирует метрики из файла, запись связывается с нужной публикацией и показывает источник и дату данных. Сводка ранжирует публикации, вышедшие в выбранный период, внутри одной площадки по выбранной метрике с указанием окна замера. Изменение числа подписчиков показано при наличии данных на обе границы периода. |
| Отчёт агента и референсы | Даны метрики и добавленные ссылки с заметками о чужих публикациях. Когда владелец передаёт сводку и выбранные ссылки своему агенту по инструкции из проекта, он может получить выводы со ссылкой на цифры и идеи для следующего плана. Выбранную идею можно добавить в план вручную. |
| Локальная работа и портфолио | Дан публичный репозиторий. Когда новый пользователь следует инструкции, он запускает приложение без обязательной регистрации, создаёт проект и находит его после перезапуска. Публичное демо открывается отдельно с вымышленными данными. |

## Сущности

Проект объединяет работу над брендом, клиентом или направлением. Площадка задаёт форматы, метрики и чек-лист. Карточка описывает контент-план, сценарий, раскадровку, обложку, публикацию или аналитику. Публикация — запланированный или состоявшийся выход материала на конкретной площадке. Шаблон — основа новой карточки или материала. Замер — значение метрики за дату или период с указанием источника. Референс — внешняя ссылка с заметкой владельца.

## Поведение при сбоях и приёмка

- План и карточки доступны локально без подключения к соцсетям. Рабочие данные и доступы хранятся отдельно от публичного демо и репозитория.
- В календаре показаны выходы публикаций по дате, включая отдельную карточку для каждой адаптации идеи. Сценарии, раскадровки и обложки открываются как связанные карточки. Замеры видны в аналитике публикации или площадки. Просрочка считается по незакрытому сроку подготовки или пропущенной дате выхода, и дашборд указывает причину.
- Импорт показывает ошибки и несвязанные строки. Владельцу доступны исправление файла и импорт валидных строк. Совпадающий замер по площадке, объекту, метрике, источнику и окну обновляется по подтверждению без дубля. Отсутствующие данные так и помечаются. Показатели с разными окнами не участвуют в одном рейтинге.
- Первый локальный тест на реальном проекте владельца проходит успешно, когда агент получает через авторизованный MCP идентификатор или ссылку хотя бы одной публикации и один показатель с датой либо периодом, а после импорта владелец видит совпадающее значение в её карточке и сводке. Затем он переносит в план идею из отчёта агента. Если доступ или данные недоступны, ручной импорт проверяет приложение, а проверка пути через MCP остаётся открытой. Конкретную площадку выбираем по доступности данных.

## За пределами первой версии

Прямая синхронизация с площадками, автопостинг и редактирование постов в соцсетях идут отдельными этапами. Совместное редактирование, роли и облачная синхронизация требуют отдельной версии. Референсы добавляются вручную, автоматический мониторинг конкурентов и рекомендации внутри самого приложения в объём не входят.
