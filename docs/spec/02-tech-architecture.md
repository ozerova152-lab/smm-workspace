## Бюджет и ограничения по инструментам

Бюджет первой версии — 0 ₽ в месяц по рабочему допущению, исходя из согласованного бесплатного локального режима. Разовые покупки и платёжная карта для выбранной схемы не требуются. Зафиксированы локальная работа одного владельца без регистрации, публичный репозиторий с отдельным демо и пробный импорт через уже настроенный MCP. Стоимость стороннего агента и подключений зависит от настроек владельца и не входит в стоимость приложения.

## Компоненты

| Компонент | Инструмент | Цена | Назначение |
|---|---|---|---|
| Интерфейс | React, TypeScript, Vite | 0 ₽ | Один набор экранов для рабочей копии и портфолио. Календарь, доска, список и дашборд читают одни записи. |
| Локальный запуск | npm и Vite на стабильном адресе, привязанном к 127.0.0.1, с фиксированным портом | 0 ₽ | После установки пользователь запускает программу на компьютере и открывает её в браузере. Занятый порт выдаёт ошибку с инструкцией. |
| Хранилище | IndexedDB, версия схемы и резервная копия JSON | 0 ₽ | Сохраняет записи в профиле браузера. Экспорт и восстановление переносят данные между устройствами вручную. |
| Обмен данными | CSV по шаблону и выгружаемая сводка для агента | 0 ₽ | Метрики попадают в приложение через импорт, выводы помогают обновлять план. |
| Публичное демо | GitHub Pages, статическая сборка | 0 ₽ | Интерактивное портфолио на вымышленных данных. Изменения в демо живут до перезагрузки. |

Рабочая копия после установки использует локальные ресурсы. Её записи доступны в том же профиле браузера по тому же адресу и порту. При очистке данных браузера восстановление возможно из сохранённой копии. GitHub Pages используется для демонстрации. Текущие ограничения включают 1 ГБ на опубликованный сайт и мягкую квоту 100 ГБ трафика в месяц. [Ограничения GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits) · [Сборка Vite](https://vite.dev/guide/static-deploy.html) · [IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API)

## Схема данных

| Набор записей | Ключевые поля и связи |
|---|---|
| Проекты | ID, название, описание. Один проект содержит площадки, карточки и заметки. |
| Площадки | ID проекта, название, форматы, определения метрик с единицами и окнами, чек-лист. Профиль копируется из каталога или создаётся вручную. |
| Карточки | ID проекта и при необходимости площадки, тип, заголовок, ссылка на общую идею или родительскую публикацию, формат, аудитория, производственный статус, сроки, ссылка и следующий шаг. У публикации есть плановая и фактическая даты выхода, внешний ID при наличии и отметка архива. |
| Шаблоны | ID, тип, тело и необязательная привязка к площадке. Применение создаёт редактируемую копию. |
| Заметки к стратегии | ID проекта, цель, аудитория, гипотеза и период. |
| Замеры | ID площадки и при необходимости публикации, метрика, значение, источник, тип окна и границы либо дата снимка. Замеры аудитории относятся к площадке. |
| Референсы | ID площадки, URL и заметка. |

«Убрать из плана» архивирует публикацию и её связанные производственные карточки с возможностью восстановления. Замеры сохраняются в истории. Состояние аналитики вычисляется отдельно от статуса публикации по наличию принятых замеров.

Фильтр периода использует фактическую дату выхода. Рейтинг внутри площадки сравнивает одну метрику в одинаковых календарных интервалах или за одинаковый срок после выхода. Точечный снимок без указанного интервала виден в карточке. Прирост аудитории — разница между снимками подписчиков на обе выбранные даты. При нескольких снимках за день берётся последний для выбранного источника, при пропуске показывается «Нет данных».

## Внешние источники и обработка ошибок

Агент пользователя читает разрешённые данные через отдельно настроенный MCP и готовит CSV. Интерфейс импортирует его в выбранную площадку. Связь с публикацией устанавливается по внешнему ID или ссылке. При отсутствии совпадения или нескольких совпадениях владелец выбирает карточку вручную либо пропускает строку. Подтверждённые валидные строки сохраняются одной транзакцией. Ключ замера включает площадку, объект, метрику, источник и окно. Новое значение для того же ключа заменяет старое после подтверждения. При недоступности MCP доступны ручной ввод и CSV. Сквозной тест через MCP остаётся отдельной проверкой.

Сводка для агента включает выбранные публикации или ссылки, показатели, значения, источники, даты или окна и референсы. Инструкция просит привязывать выводы к цифрам и предлагать идеи для ручного переноса в план. Входные файлы и сводки обрабатываются локально, передачу выбранной сводки своему агенту инициирует владелец. Токены хранятся в настройках авторизованного коннектора. Репозиторий и публичная сборка содержат только примеры на вымышленных данных.

## Открытый вопрос

Конкретную площадку для локального теста выберем после проверки доступности метрик публикации в уже авторизованном MCP. Способ запуска и проверки на чистом компьютере детализируем в слое 3.
