## Запуск

На чистом компьютере пользователь устанавливает Node.js 24 LTS с npm, распаковывает архив проекта или клонирует репозиторий и один раз выполняет `npm ci` по инструкции. Затем `npm start` открывает доступ к рабочей копии по адресу `http://127.0.0.1:3000`. Начальный экран пустой, вход по аккаунту отсутствует. Порт фиксирован. Если он занят или недоступен, команда сообщает об этом и завершается. Можно явно выбрать другой фиксированный порт с предупреждением, что данные прежнего адреса не переносятся автоматически. При повторном запуске в том же профиле браузера рабочие данные доступны по тому же адресу.

## Тестовые данные и сброс

Вымышленный набор содержит два проекта, несколько форматов и площадок, связанную идею с адаптациями, сроки, шаблоны, заметку к стратегии и референсы. Есть CSV с валидной строкой, ошибкой, повторным замером и строкой без однозначной привязки. Фиксированные замеры покрывают разные окна и снимки подписчиков. Публичное демо берёт только вымышленный набор и хранит изменения до перезагрузки. Автопроверки стартуют с нового браузерного контекста и тестового адреса. Повторный запуск тестов возвращает этот контекст в чистое состояние.

## Как проверяем

| Сценарий | Действие и наблюдаемый результат |
|---|---|
| Запуск с нуля | По README установить зависимости, запустить приложение и создать проект. После перезапуска проект и карточка видны в том же профиле по адресу `http://127.0.0.1:3000`. Второй запуск при занятом порте завершается с ненулевым кодом и понятной подсказкой. |
| Дашборд | Открыть два проекта с известными сроками. За два выбранных периода сверить запланированные, опубликованные и просроченные карточки по каждому проекту, ближайшие выходы и причину просрочки. Открыть задачу и увидеть следующий шаг. |
| Площадка и контент-план | Добавить площадку из каталога и свою площадку. Настроить формат, метрику и чек-лист, сверить их на странице площадки и в связанных действиях. Создать две адаптации и сценарий, перенести публикацию и сверить дату, статус и общие фильтры во всех трёх видах. Архивация скрывает публикацию из плана, восстановление возвращает её со связями. |
| Шаблоны и стратегия | Применить шаблон, изменить копию и сверить исходный текст. Сохранить гипотезу в проекте, заново открыть её из контент-плана. |
| Аналитика, CSV и сводка | Внести замер вручную и проверить переход от «Ожидает данных» к «Обновлено». В CSV проверить ошибки до записи, ручное сопоставление и обновление без дубля. Сверить порядок двух публикаций по известным значениям за одинаковое окно, отдельный замер за другое окно и прирост из двух снимков. При пропуске снимка должно быть «Нет данных». Сверить поля выгруженной сводки, затем открыть вымышленный отчёт и перенести идею в план. |
| Резервная копия и демо | Экспортировать рабочий проект, восстановить в чистом контексте и сравнить карточки и замеры. Открыть отдельную статическую сборку демо, сверить вымышленный набор, изменить карточку и проверить её сброс при перезагрузке. В том же браузере убедиться, что рабочая запись сохранилась по локальному адресу. |
| Живой тест MCP | С разрешения владельца агент читает метрику одной публикации и готовит CSV. После импорта сверяем публикацию, значение и дату или период с источником, получаем рекомендацию и переносим идею в план. При недоступности данных результат проверки отмечается отдельно от ручного прогона. |

## Инструменты и доказательства

- `npm run check` проверяет типы, правила кода, расчёты и импорт, затем собирает приложение. `npm run test:e2e` запускает ключевые действия в Chromium через Playwright. Браузер для тестов устанавливается по инструкции один раз. Изолированные контексты и трассировка помогают повторить сбой. [Изоляция Playwright](https://playwright.dev/docs/browser-contexts) · [Трассировка](https://playwright.dev/docs/trace-viewer) · [npm ci](https://docs.npmjs.com/cli/v11/commands/npm-ci)
- Команды запуска, проверки и сброса тестового окружения описываются в README и `AGENTS.md`. Мини-скиллы проекта ведут агента по этим же командам. После ошибки агент открывает трассировку, исправляет причину, повторяет сценарий и прикладывает результат проверки, например видимую карточку или сверенное значение из сводки.
- В автопроверках внешний агент и MCP заменены подготовленным CSV и ожидаемой сводкой. Реальный CSV, резервные копии, секреты и материалы живого теста хранятся вне репозитория. Публичные отчёты и скриншоты используют вымышленные данные.
